### Minor

- **m1. Text input borders are 1.27:1 (light) and 1.19:1 (dark) against the card, below the 3:1 of WCAG 1.4.11.**
  - The designer's flag is confirmed. `TextField`, `TextArea`, `MoneyField`, the rule `select` (`CategoryRulesCard.tsx:271-285`) and the friend input (`FriendsScreen.tsx:107-124`) use `border-border` (light `#e4e4e7` on `#ffffff`, dark `#27272a` on `#18181b`, `theme.css:14`, `:89`, `:123`). The fields have the same fill as the card, so the border is the only thing that shows where the field is.
  - WCAG 1.4.11 asks 3:1 for "visual information required to identify user interface components". A visible label above the field helps, but it does not show the input's area. Palavra-chave and Nome do amigo have no placeholder, so at rest they are two faint lines (`$A/view-360-s-default.png`, `$A/view-360-friends.png`). The select has a chevron, and MoneyField and Justificativa have placeholder text, which helps, but their boundary is the same.
  - This predates 012: 008 n7 recorded it as informational and suggested a fix in 010, and it was not done. 012 adds four more fields with the same style, and AC16 asks for accessible inputs, so it is now graded minor and not left informational. The focus state passes (2 px `accent-text` ring, 5.02 / 10.61).
  - **Fix:** in `theme.css`, add one token for field borders, for example `--color-field-border`: light `#8b8b94` (3.38:1 on `surface`), dark `#71717a` (3.67:1 on `surface`), with a one-line comment. Then use `border-field-border` instead of `border-border` in the rest state of `ui/TextField.tsx`, `ui/TextArea.tsx`, `ui/MoneyField.tsx`, the rule `select` and the friend input. Keep `border-danger` for errors and the amber border on focus. Cards and dividers keep `border`. Add the pair to the design skill's contrast table. Then rerun the layout scan (`$A/scan.cjs`) and the contrast check in both themes, and look at the login and Novo gasto screens, which share these fields.

### Informational

- **n1. Focus falls to `body` after a submit by button.** `AdjustBalanceCard.tsx:173`, `CategoryRulesCard.tsx:241` and `FriendsScreen.tsx:130` set `disabled` while saving, so the focused button loses focus. That happens on success and on an API error for Ajustar saldo and Regras, and on success for Amigos (E10). The status or alert line is announced, and the next Tab goes on from the button's place, so a keyboard user does not lose their position. A screen reader user may hear the page context again. The delete buttons already avoid this with `aria-disabled` (`CategoryRulesCard.tsx:176`). Optional: use `aria-disabled` plus the existing ref guard on the three submit buttons, or move focus to the result line.
- **n2. The history item that "Ver todos" focuses has no visible indicator** (`AdjustmentHistory.tsx:127`, `outline-none` with `tabIndex={-1}`). It is not interactive and the next Tab goes to the next control, so 2.4.7 does not strictly apply. Optional: give it the `focusRing` outline while focused.
- **n3. Long user keywords show about 10 characters at 360 px** ("supermerca...", `$A/scan/claro-360-s-default.png`) because the pill, the category and the delete button take the rest of the row. The full keyword is in `title` and in the delete button's name, and friend names truncate in the same way, as the plan says. Optional: let the keyword wrap (`break-words` without `truncate`) or move the category under it below 400 px.
- **n4. API errors on the rule and friend forms are not tied to the field.** The 409 and the API 422 render in `role="alert"` under the form (`FormFeedback`), so they are announced, but the field does not get `aria-invalid` or `aria-describedby`. AC16 asks for both on the field's own validation errors, which pass. No action needed.
- **n5. "Saldo atual" and the reason validation use the last loaded balance while it reloads.** A submit made during the short reload after an adjustment compares with the previous balance. The API always computes the delta against the real balance (Data Rules), so the stored value is right; the worst case is a "Diferença" or "igual" message from a stale value for a moment. No action needed.
- **n6. Commits.** `f06494c` combines a `refactor(web)` rename with the docs sync and a spec clarification in one commit, and `7da6df8` (`style(web)`) also ticks `tasks.md`, which is against "one logical change per commit" (same as 009 n5, 010 n6 and 011 n5).
